# 頂点コート(chouten-court)— MVP 設計規格書

> 台灣高中籃球球隊經營模擬遊戲。教練視角,經營一支高中球隊,目標是拿下 HBL 甲級總冠軍。

## 1. 專案定位

- 純前端、無後端,部署 GitHub Pages,PWA(可加入主畫面)。
- 技術棧:Vite + React + TypeScript。
- 單機遊戲,無排行榜、無跨玩家資料比對。

## 2. 核心時間系統

- 全年以「週」為單位推進。
- 賽季對應 HBL 甲級五階段:資格賽 → 預賽(單循環) → 複賽 → 八強賽(淘汰) → 四強賽(淘汰,單場定勝負),約 22 週。
- 非賽季(約 26 週)用於招生、訓練、練習賽。
- 一屆 = 3 年(高中學制),教練生涯可連續帶多屆。

## 3. 生涯結構與結局

- 教練生涯連續帶多屆,直到達成勝利條件或觸及保險上限。
- **勝利條件**:拿下 HBL 甲級總冠軍 → 生涯結局,顯示生涯總結。
- **保險上限**:6 屆(約 18 年,約 650 週)內未奪冠 → 強制結束,生涯總結收尾。
- 每屆開局可選**起始情境**(例如「新手教練接弱校」低聲望起步 / 「老牌名校接班」高聲望起步),影響初始聲望與名冊強度。

## 4. 球隊與球員資料模型

- 單一名冊,10~12 人,不分一軍/二軍。
- 7 項屬性:投籃、三分、籃板、傳球、防守、運動能力、IQ。
- 每位球員額外欄位:
  - 疲勞值(0~100)
  - 個性標籤(招生時固定,見第 9 節)
  - 傷病狀態(健康 / 輕傷 / 重傷 / 復出過渡期)
  - 球風標籤(由屬性即時計算,見第 10 節)

## 5. 招生系統(簡化球探版)

- 每年產生新生候選池,候選人屬性只顯示**區間**(例如「投籃 55~75」)。
- 玩家每週有限量「球探點數」,可用於窄化候選池中特定球員的特定屬性區間。
- 招生截止時,玩家直接從候選池選人收隊 — **不做拒絕/交涉機制**。
- 候選池整體品質(高潛力球員出現機率)受學校聲望影響,但聲望**只調整機率分佈,不設硬上限**,弱隊仍保留低機率挖到璞玉的翻身空間。

## 6. 訓練與練習賽

- 每週為「一週一個主要決策」:**訓練**或**練習賽**二選一。
- **訓練**:選擇全隊統一訓練重點與**訓練強度**(輕/中/重),個人成長幅度依天賦係數差異化,不逐人分配。
  - 強度越高,該項屬性單週成長越多,但當週疲勞消耗也越多——輕/中強度仍是淨恢復,重強度會讓疲勞淨增加,直接連動第 11 節的受傷風險,逼玩家在「衝快」與「顧身體」之間取捨。
- **練習賽**(僅非賽季):
  - 自選對手強度(弱/中/強),強度越高、贏了成長越多,輸了成長少或有小懲罰。
  - 依比賽結果給差異化球員成長,**不影響聲望**(非正式賽事)。
  - 頻率上限:每月最多 1 次;賽季開打前 2~3 週封鎖,強制回歸訓練備戰。

## 7. 比賽模擬

- 全自動模擬(不中途互動),依雙方球員屬性、疲勞係數、戰術旋鈕運算出結果。
- 賽前戰術旋鈕(MVP 僅做 2 組):
  - 進攻節奏:快攻 / 半場陣地戰
  - 防守策略:盯人 / 聯防
- 疲勞值影響該場模擬的屬性表現係數。

## 8. 對手球隊

- 不做完整對手名冊,只維護:
  - **強度值**:依賽制階段遞增(資格賽弱、四強強)。
  - **王牌選手**:固定屬性(得分、三分等關鍵項),**每屆重新生成一次**,同屆 3 年內不變。
- 對手校名稱使用**生成規則**(地名 + 常見校名後綴),不對應現有 HBL 球隊正式名稱。

## 9. 球員個性(招生時固定,6 種)

| 個性 | 效果 |
|---|---|
| 穩健型 | 全屬性均衡成長,比賽表現變異度低 |
| 天才型 | 練習/比賽成長效率最高,候選池出現機率低(稀有) |
| 飆分型 | 投籃/三分相關成長較快,比賽表現變異度高 |
| 隊長型 | 在場時全隊當週疲勞回復/成長有小幅加成 |
| 抗壓型 | 淘汰賽階段(八強、四強)表現額外加成 |
| 玻璃體質 | 受傷機率係數較高,但屬性成長上限較高 |

效果直接作用於既有屬性/疲勞欄位,不另建特殊能力系統。

## 10. 球風標籤(原創公式,待調校)

- 由 7 項屬性計算出多維度球風分數(例如得分、射手、組織、防守、籃板傾向),取主要/次要傾向自動生成敘事型標籤(例如「雙向側翼」)。
- **具體加權係數為本專案原創設計,尚未調校,需在實作時依遊戲平衡反覆測試決定**,不沿用任何外部專案的既有數值。
- 純粹由現有屬性計算而來,不新增資料欄位,不是玩家可操作的系統。

## 11. 疲勞與受傷

- 每球員疲勞值(0~100),每週結算:疲勞值變化 = 當週行動負荷 − 基礎自然回復量。
  - 比賽週/練習賽週負荷較高,淨值上升;純訓練週負荷低,淨值下降(自然恢復)。
- 疲勞值只在**週結算**與**比賽模擬係數**中起作用,不做逐場/逐節體力管理。
- 受傷觸發:比賽結算時依當下疲勞值滾機率,疲勞越高機率越高。
- 受傷後果(兩級,無永久後遺症):
  - 輕傷:缺賽 1~2 週,疲勞值強制歸零。
  - 重傷:缺賽較長(視賽制階段而定),復出後 1~2 週屬性打折(例如 8 折),之後恢復正常。

## 12. 聲望系統

- 單一聲望數值,依每屆賽季戰績(晉級到哪個階段、最終名次)調整。
- 影響新生候選池品質的**機率分佈**,不設硬性天花板/地板。

## 13. 名人堂與球星比對彩蛋(原創,待調校)

- **名人堂**:記錄效力過的球員中數據最好/貢獻最大者,做「校史名人牆」。
- **球星比對彩蛋**:維護一份小型參考球員屬性表,以距離公式找出與該球員最相似的對象,產生 flavor text(例如「他的打法讓球探想起某位球星」)。用於招生候選人亮點或畢業生後日談。**參考表內容與距離公式為本專案原創設計**,不引用任何外部專案的既有資料。

## 14. 種子碼分享

- 新遊戲開局可選填種子碼,決定論亂數(招生候選池、事件)可依種子重現。
- 用途:玩家間可用同一份種子碼比較「同運氣、誰帶得更好」,純選填,不需要伺服器比對。

## 15. 畢業生後日談

- 球員畢業時,依其最終屬性、個性標籤、當時球隊聲望,做一次加權隨機判定其「去向」(例如大學聯賽/一般升學/職業機會)。
- 產生一段簡短敘述文字,存入名人堂資料。
- **不可互動、不影響主線任何數值**,純粹是一次性擲骰 + 文字模板。

## 16. 總結畫面

- **單季總結**(每屆每季結束):戰績、隊內數據王、獲得獎項。
- **生涯總結**(遊戲結局觸發):生涯總戰績、奪冠陣容(若有)、名人堂精華、聲望曲線、畢業生後日談彙整。
- **戰績分享卡**:生涯總結可產生可下載圖卡,純個人紀念用途,不涉及排行榜或跨玩家驗證。

## 17. 成就/稱號系統

- 達成特定條件(例如零受傷賽季、連續八強)解鎖徽章,純紀錄性質,不影響數值運算。

## 18. 宿敵校追蹤

- 記錄對特定對手校的歷屆交手戰績,累積「宿敵指數」,與對手王牌選手機制串連。

## 19. 命名系統

- 玩家自己的球隊名稱、教練名稱:開局自訂輸入。
- 對手校名稱:生成規則(地名 + 校名後綴),不對應現有 HBL 球隊正式名稱。

## 20. 存檔系統

- localStorage 單一存檔,不做多存檔槽。
- 建議加入主畫面(PWA)以避免 Safari 7 天閒置清除機制清掉存檔。
- 匯出/匯入 JSON 備份:匯入時做格式驗證(必要欄位/型別檢查),格式錯誤時拒絕載入並提示,不做防竄改機制。
- **已知限制(接受)**:純前端無後端架構下,無法防止使用者透過瀏覽器 console 直接修改記憶體中的遊戲狀態。此為純前端單機遊戲的固有限制,不影響任何其他玩家,不列入防護範圍。Production build 的變數名稱最小化(minify)順帶提高隨手竄改的門檻,但非安全機制。

## 21. 視覺呈現

- 球員頭像:DiceBear `pixel-art` 風格,以球員唯一 ID 當種子動態生成 SVG,疊加球隊配色與背號。
- 純程式運算生成,不需要外部美術資源或 AI 圖片生成 API。

## 22. 明確排除的範圍(MVP 不做)

- 完整對手球隊名冊(僅強度值 + 王牌選手)。
- 逐場/逐節體力管理與臨場戰術操作(比賽全自動模擬)。
- 傷後永久能力下降或舊傷復發機制。
- 多存檔槽、雲端同步。
- 音效/BGM。
- 防竄改/反作弊機制。
- 畢業生後續的可互動生涯模擬。

## 23. 授權與原創聲明

本規格所有數值公式、參考資料表、平衡係數均為本專案原創設計,尚待實作與遊戲測試階段調校,不移植任何外部專案的既有程式碼或資料。
