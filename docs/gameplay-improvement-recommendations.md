> 目的：將《野球魂》白球模式的研究結論，轉化為適合本專案高中籃球經營玩法的改善方向。

## 1. 結論

目前專案已具備完整的 MVP 骨架，包括每週訓練、練習賽、正式賽季、疲勞與受傷、招生、畢業、聲望和生涯總結。

現階段最需要補強的不是更多事件、成就或收藏內容，而是讓以下三件事互相影響：

1. 球員是否上場及其角色。
2. 球員的疲勞與恢復。
3. 現在贏球和培養下一屆球員之間的取捨。

《白球のキセキ》最值得借鑑的部分，不是棒球專屬的投手系統，而是讓短期戰績、球員養成與跨年度經營形成持續拉扯。對 `chouten-court` 而言，應以先發、輪替、上場時間與恢復選擇來達成相同效果。

## 2. 第一優先：建立先發與輪替系統

目前比賽會將所有健康球員平均計入球隊戰力，沒有區分先發、替補或未上場球員。因此 12 人名冊的組成、板凳深度與球員起用尚未形成實際決策。

建議加入最小版本的出賽配置：

- 選擇 5 名先發球員。
- 選擇 3 名主要輪替球員。
- 其餘球員本場不出賽。
- 先發承受最高比賽負荷。
- 主要輪替承受中等比賽負荷。
- 未出賽球員獲得較完整的恢復。
- 球隊戰力由先發與輪替加權計算，不再平均計算整份名冊。

建議的初期模型：

```text
球隊戰力
= 先發五人有效戰力 × 主要權重
+ 主要輪替有效戰力 × 次要權重
+ 戰術與個性修正
```

這項改善完成後，才能合理承接隊長型的在場加成、疲勞輪休、板凳深度和新人培養。

## 3. 第二優先：讓比賽起用同時影響養成

目前球員參加正式比賽不會因上場角色獲得不同的實戰成長。玩家因此沒有理由犧牲短期戰力培養低年級球員。

建議採用輕量規則：

| 出賽角色 | 實戰成長 | 疲勞負荷 | 用途 |
|---|---:|---:|---|
| 先發 | 高 | 高 | 主力爭勝、核心養成 |
| 主要輪替 | 中 | 中 | 維持戰力、培養接班人 |
| 未出賽 | 無 | 低或恢復 | 輪休、傷後保護 |

初期不必建立複雜的經驗值等級。可以在比賽結算時，依出賽角色給予小幅屬性成長機會，之後再視遊戲測試結果決定是否增加信賴度或關鍵比賽經驗。

預期形成的核心決策是：

```text
使用高年級主力提高本場勝率
vs.
讓低年級球員提早累積實戰成長
```

## 4. 第三優先：拆分訓練狀態與比賽負荷

目前每名球員只有一個 `fatigue`，同時代表訓練疲累、近期比賽負荷、受傷風險與比賽表現下降。這使不同原因造成的疲勞難以被玩家理解，也限制了恢復策略。

建議拆成兩項狀態：

```ts
interface PlayerCondition {
  trainingEnergy: number
  gameFatigue: number
}
```

兩者責任如下：

- `trainingEnergy`：影響訓練成功率或成長量，由訓練強度與休養調整。
- `gameFatigue`：影響比賽表現與受傷風險，由出賽角色、賽程密度與休息調整。

這可表達目前單一數值無法清楚表達的情境：

- 球員可以參加訓練，但不適合在下一場擔任主力。
- 球員比賽負荷不高，但因連續高強度訓練而成長效率下降。
- 板凳球員因上場較少而保持良好比賽狀態。

這是一項資料模型變更，建議在先發與輪替規則確認後再實作，以免先建立沒有實際用途的欄位。

## 5. 增加可靠的恢復選擇

目前玩家主要透過低強度訓練和隨機事件減輕疲勞，缺少可預期、可主動選擇的休養方式。

建議非賽季每週提供四種主要行動：

1. 正常訓練：一般成長與一般負荷。
2. 低強度調整：少量成長並恢復部分狀態。
3. 全隊休養：放棄當週成長，取得最大且確定的恢復。
4. 練習賽：取得實戰成長，但增加比賽負荷與受傷風險。

休息必須具有機會成本，但不應依賴隨機事件才能發生。如此高強度訓練才會產生玩家可以預測和處理的延後代價。

## 6. 改善賽前與結算資訊透明度

研究文件的核心原則之一，是玩家應理解狀態變化的原因，而不是只看到最終結果。

建議賽前顯示：

- 目前預估勝率或雙方戰力比較。
- 疲勞造成的戰力折損。
- 每名先發與輪替球員的預估疲勞變化。
- 高受傷風險警告。
- 戰術對本場能力權重的影響。

建議賽後顯示：

- 哪些球員實際上場。
- 每名球員增加或恢復多少疲勞。
- 哪些球員取得實戰成長。
- 傷勢發生的主要風險因素。

隨機性可以保留，但玩家應能分辨結果來自陣容、戰術、疲勞還是隨機波動。

## 7. 補完既有球員個性

目前隊長型與抗壓型只有標籤，尚未產生實際效果。建議等先發與輪替系統完成後再補上：

- 隊長型：只有列入先發或主要輪替時，才給予小幅團隊恢復或表現加成。
- 抗壓型：在八強與四強階段提高個人有效表現。
- 玻璃體質：目前已有較高受傷率，應補上規格提到的成長優勢或較高成長上限，避免成為純負面個性。

所有加成初期都應保持輕量，避免個性效果蓋過球員的實際屬性與玩家決策。

## 8. 已發現的規格與實作落差(已解決)

### 訓練骰子規則不一致

規格寫明每名球員各自擲一顆 1～6 的骰子；程式碼前段註解也描述為每人各擲，但當時實際執行一度是全隊共用同一顆骰子。

**已裁定採用規格原本的「每人各擲」**(見 `docs/gameplay-improvement-specs.md` 第 7 節):每位可訓練球員各消耗一次決定論亂數，分別判定成功、失敗與會心一擊，`docs/spec.md` §6、程式碼與訓練結果畫面現已三方一致。

## 9. 暫緩項目

以下內容能增加收藏或敘事深度，但目前不會直接改善每週決策，建議暫緩：

- 名人堂完整畫面。
- 球星比對彩蛋。
- 成就與稱號。
- 宿敵校追蹤。
- 更多隨機事件卡。
- 複雜的學校設施與設備耐久。

待先發輪替、起用養成和疲勞決策形成穩定循環後，再加入上述內容會更有價值。

## 10. 建議實作順序

```text
1. 先發五人與主要輪替選擇
2. 依出賽角色計算球隊戰力與疲勞
3. 上場角色帶來不同的實戰成長
4. 賽前負荷、勝率與風險預覽
5. 訓練狀態與比賽負荷分離
6. 全隊休養與低強度調整
7. 隊長型、抗壓型與玻璃體質效果
8. 學校設施與跨年度資產
9. 名人堂、成就與宿敵等長期內容
```

前四步完成後，遊戲應能形成第一個可感知的新循環：

```text
安排先發與輪替
→ 評估勝率、疲勞與受傷風險
→ 完成比賽
→ 主力累積負荷、新人取得成長
→ 調整下一場陣容
```

這個循環比單純增加更多數值或事件，更能直接提升高中籃球教練經營的核心體驗。
